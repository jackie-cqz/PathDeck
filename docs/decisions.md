# PathDeck 开发决策

## 2026-10-30 · M0

### D001：AppKit 主界面与 macOS 14 部署目标

遵循用户指定的 Swift + AppKit。主界面用代码构建，不依赖 storyboard/nib；窗口、分栏、表格、文本、菜单都使用原生控件。保持 macOS 14.0 deployment target，目前运行验证仅覆盖 macOS 27.2 arm64。

### D002：标准 Xcode 工程 + 无外部依赖的 SwiftPM 构建

本机只有 Command Line Tools，`xcodebuild` 不可用。提供 `.xcodeproj` app/test target 与共享 scheme，同时用 SwiftPM 编译相同 AppKit 源码。`build-app.sh` 将实际可执行文件和同一 Info.plist 组成 `.app`，本地 ad-hoc 签名，不借用开发者账号。

Python 标准库生成工程，稳定对象 ID，不依赖联网安装 XcodeGen。`--check` 比较当前源文件与生成结果，检测工程漏收新增文件。没有声称通过 Xcode 实际构建。

### D003：共享 Core 与测试源码

SwiftPM 使用独立 `PathDeckCore` library；Xcode app target 直接编译同一组 Core 源文件，测试通过条件 import 引用对应模块。这样首个骨架不需要额外动态 framework 与嵌入步骤。后续真正需要多个 native target 共用时，可以迁为本地 package/framework，避免过早增加工程复杂度。

Core 初始化不读取文件系统。`FileItem.id` 当前是 URL 的路径级回退标识，不代表持久文件实体身份；M1/M2 引入 DirectoryReader 与真实资源身份时需继续完善外部重命名与动作前复核。`DirectoryNode.ID` 包含分支，避免同一路径在 Favorites/Locations 的行冲突。

### D004：先建立状态边界，再接入磁盘 IO

`BrowserSession` 在 MainActor 上维护每窗口状态。开始导航只更新 pending request；只有匹配请求成功才能提交当前目录与行数据，失败保留已提交位置。request UUID 隔离不同窗口，generation 给后续异步加载使用。M0 没有 DirectoryReader、导航历史或完整 coordinator；状态单元测试不代表真实目录导航已完成。

### D005：未实现能力明确展示阶段

M0 展示真实 Home 路径，路径文字可选择复制，导航按钮禁用并说明将在 M1 开放；侧栏是布局说明；文件区域明确显示“目录尚未读取”。不填充虚构文件数据，也不把未读取状态当空文件夹。正常菜单支持退出、关闭、重新显示、文本编辑和窗口操作。

### D006：测试框架与工具链适配

当前 Command Line Tools 不提供 XCTest，提供 Swift Testing，因此采用 Swift Testing。Swift 6.4 默认 swiftbuild 后端缺少 TestingMacros 自动加载，包装脚本从当前选中的 swiftc 所在工具链查找自带插件并显式传给编译器。原生旧后端也缺少 Testing 搜索路径，因此最终仍采用默认构建后端。脚本不修改系统安装；未引入第三方包。

### D007：启动验收与构建检查分开

`--smoke-test` 是 opt-in 的真实 AppKit 启动检查：窗口可见、布局尺寸、Home 路径、列表列、菜单，检查后退出。正常启动不会运行或自动退出。该检查用于 M0 启动基础，不代替 XCUITest、VoiceOver 人工验证、兼容性或文件操作测试。

用户当前仅要求 M0，后续 M1–M3 保留在 SPEC.md 中，未在本轮展开。

## 2026-10-30 · M1

### D008：先实现只读导航闭环

按用户最新要求，推进 M1，优先实现输入路径、跳转目录、真实文件列表。随后接入面包屑、补全、历史、惰性目录树和只读右键操作。M2 写操作不在本轮开放。

### D009：目录 IO 与界面状态分离

`DirectoryReader` 用最多两个并发任务的后台 OperationQueue 执行阻塞式文件访问。`NavigationCoordinator` 负责语法解析/异步读取，`BrowserSession` 只在匹配最新请求时提交。历史保存选择、排序、滚动锚点，刷新不新增条目；失败保留原位置与行数据。

### D010：真实路径与行身份统一

测试发现 Foundation 对 `/var`、`/private/var` 的显示标准化与实际枚举返回值可能不同，导致目录已打开但文件选中/目录树定位不匹配。后台使用 `realpath` 获取存在目录的物理路径；选中项目复用本次枚举产生的 URL，统一目录与文件 URL 语义。地址栏显示真实目标路径；输入文件路径不会自动打开文件。真实目录优先的原则不改变用户文件。

### D011：隐藏祖先与目录树

目录树默认隐藏隐藏目录，不跟随目录 symlink 递归。在显式跳转的路径包含隐藏祖先时，局部加载该祖先链并只显露必需节点，避免 `/private` 等目录被默认隐藏规则阻断定位。每个树节点复用加载任务与占位对象，避免异步展开产生重复身份。

### D012：补全与焦点

补全停顿 150 ms 后异步读取直接子目录，最多 20 项；用非激活浮层保留路径输入焦点。上下键选择、Tab 接受、Enter 跳转，IME 组合输入不触发导航。显式切换焦点期间忽略旧编辑结束通知，防止旧会话把新会话误取消；过期补全按 revision 丢弃。

### D013：工具链状态变化

M1 开发期间检测到 Xcode 已安装并成为默认 Developer directory，但工具报告首次许可未确认。验证命令以 `DEVELOPER_DIR=/Library/Developer/CommandLineTools` 指定原有工具链；没有自动接受 Xcode 许可，也没有改变系统默认工具链。完整 Xcode build/test 待用户完成首次设置后补验。

### D014：当前原型边界

M1 不实现文件写操作。完整快捷键方案设置、列配置/窗口状态持久化、目录监控和大目录性能验收仍按后续里程碑推进。终端入口、常用项显示别名/重排暂未实现；已实现的只读菜单入口有实际动作。系统图标当前使用原生 SF Symbols 通用类型图标，缩略图与按文件类型缓存图标后续优化。

## 2026-10-30 · M2

### D015：继续使用 Command Line Tools

用户明确要求暂不使用 Xcode。因此本轮所有构建与测试显式指定 `DEVELOPER_DIR=/Library/Developer/CommandLineTools`；只由 Python 生成兼容工程配置，没有运行 Xcode build/test。

### D016：统一串行写队列与物理对象身份

写操作统一由 MainActor 的 `FileOperationService` 调度，一条专用后台队列执行 Foundation/POSIX 文件 IO 与 NSFileCoordinator 协调。操作捕获源/目标的设备号、inode、创建时间和对象类型，执行前重新校验。设备号按其 32 位位模式编码，避免负的 dev_t 直接转换为 UInt64 造成崩溃。

### D017：不覆盖提交与保留临时副本

新建文本使用 O_EXCL，新建目录使用 mkdirat；复制先在目标卷的唯一私有 staging 目录复制，再使用 renameatx_np(RENAME_EXCL) 发布。目标目录通过 FD 与身份再次校验。只对确认已空的 staging 调用 rmdir；失败/取消的非空副本保留并记入任务详情，不递归删除不确定内容。

### D018：剪贴板协议和部分完成

系统标准 file URLs 用于复制互操作。应用内剪切另保存会话 token、changeCount、捕获的引用，剪切本身不移动文件。完成时仅移除已成功移动的引用；失败项保留待重试。剪贴板变化会清除淡化。原生文本 responder 处理输入框复制粘贴，文件列表单独处理文件快捷键。

### D019：只支持同卷移动和系统废纸篓

移动使用同卷排他重命名，跨卷拒绝。废纸篓使用系统 API，并校验协调 URL 的身份，不退化为永久删除。删除前确认数量和名称；首版没有通用文件撤销。

### D020：任务记录、取消与退出

任务按顶层项目报告进度，不伪造单文件字节百分比。取消在安全边界生效，当前系统复制可能先结束。私有 Application Support/PathDeck/Operations 中的 JSON 记录每个任务、结果与临时位置；重启把未完成任务标为结果待核实，不自动重放。退出时可等待、请求取消或返回。

### D021：验证夹具与真实系统回收

自动化只创建并清理自己拥有的唯一临时目录。窗口检查使用私有 pasteboard；实际系统废纸篓只接收一个唯一测试文件，并使用系统返回的确切 URL 移回夹具，既不枚举也不清空已有内容。磁盘满由确定性故障注入验证，未假称真实磁盘已填满。

## 2026-10-30 · M3

### D022：有范围的 vnode 监听

不递归扫描或监听磁盘。监控当前目录、展开分支和可见文件，上限 64；后台管理 FD，200 ms 合并变化。当前目录切换立即更新，视口滚动延迟合并，避免树加载不断推迟当前订阅。关闭窗口停止，激活/手动刷新补偿遗漏。目录重命名通过 FD 路径和原身份验证后跟随，不按猜测路径跳转。

### D023：刷新保留输入与物理对象身份

刷新按身份迁移选择/滚动锚点，避免同名替换误选。地址栏草稿保持原样，失败后继续可编辑；内联重命名结束后补刷。显式导航清理旧编辑状态，外部目录改名以 refresh 模式更新同一历史位置，不抢走路径输入焦点。取消的排队导航在 beginNavigation 前退出。

### D024：统一配置与恢复边界

使用有版本 JSON、原子写入、350 ms 合并保存和退出 flush。窗口/列/侧栏/偏好/常用与最近目录集中保存；损坏和未知版本先备份，数值、路径与数组统一整理。窗口恢复限制在可见屏幕范围；失效保存位置退回 Home 并说明。M1/M2 的 UserDefaults 偏好只在首次缺少配置时迁移。

### D025：限制视图和临时状态开销

复用表格单元格，文件类型图标缓存 128，历史 50，展开恢复 128；树折叠/重建取消旧加载。监听和剪贴板 Timer 随窗口可见性停止/恢复。操作日志和失败临时副本保留可核查性，不在本轮自动清理。

### D026：实测与人工验收分别记录

Release benchmark 生成真实文件并测到列表显示，保留每次样本、机器/工具链/缓存条件、心跳和资源计数。自身 AppKit 内容视图可导出供检查，不依赖屏幕读取权限。自动 AX/焦点/外观检查不等同 VoiceOver 人工朗读；硬件/权限专项和冷缓存启动明确列为待补验。

## 2026-10-30 · 日常操作补齐

### D027：Terminal 使用目录 URL，并独立验证 cwd

通过 NSWorkspace 向 com.apple.Terminal 传 URL，后台先验证普通目录。菜单分别捕获当前目录/单个目录/树节点；不构造 shell 或 AppleScript 命令。opt-in 验收检查 Terminal 子 shell 的真实 cwd，覆盖引号、命令符号、中文与换行，并只清理唯一夹具对应的新 shell。

### D028：常用目录路径与显示名分开

兼容旧 favorites 数组，增加可选 favoriteNames 字典，避免升级将旧配置判为损坏。别名、排序、重新定位仅操作配置；不可用状态异步计算，保留修复入口。侧栏重建保留卷入口、恢复当前位置，并取消旧树加载。

### D029：完整目录快照与过滤视图分开

BrowserSession 保留 items，并维护 visibleItems 与当前查询。选择只允许可见项目，过滤后右键仍按行捕获 FileReference；不会对隐藏选择执行写操作。查询随刷新保留、随显式目录跳转清除；新建时清除查询以显示名称编辑。过滤框处理 IME 组合态，查询不加入持久化配置。


## v0.2 补充决策

### D032：原生窗口标签与应用级文件任务

每个 NSWindow/标签保留独立 BrowserSession、视图与导航任务；AppDelegate 管理打开窗口和当前命令目标，显式 addTabbedWindow 建组，关闭最后窗口后保留一个可重开的页面。禁用系统自动合并，让 ⌘N 始终表示独立窗口。全部标签会话恢复另行实现。

FileActionContext 共享一个写入服务、剪贴板和任务窗口。观察者与 browser 引用为弱引用，任务持有动作控制器到完成，因此关闭页面可释放视图同时保持待执行任务和剪切令牌。冲突选择可见浏览窗口，全部关闭时使用任务窗口；退出检查共享队列。常用目录变更单独广播，旧窗口的普通布局保存不会覆盖新的固定项。

### D033：Quick Look 控制权只有一个入口

QLPreviewPanel 为系统共享单例，在 MainWindowController 的 begin/endPreviewPanelControl 中安装/移除数据源和代理。BrowserViewController 只负责把选择交给预览对象，不再重复声明控制钩子；双重入口会导致控制权交接时代理被清空。显示面板进入响应链后再检查控制权，空格/Esc 经已安装的代理关闭并返回来源列表。不在未控制面板时改动其数据源。

依据：[Apple QLPreviewPanel](https://developer.apple.com/documentation/quicklookui/qlpreviewpanel) 与当前本机 SDK 头文件。原生标签使用 [NSWindowTabGroup](https://developer.apple.com/documentation/appkit/nswindowtabgroup) 的真实组状态。

### D034：原生层次与保守属性读取

保留用户选定的 Mint Path 图标，使用 SF 字体、动态系统背景和原生焦点/选择，玉绿色只用于辅助符号。属性不递归扫描，元数据在独立队列读取，权限只读显示。文件列表加载暂时禁用时记录原有列表焦点，加载完成后仅在没有新文本编辑时恢复。

### D035：通过正常应用启动验证窗口交互

核心测试不需要桌面激活。原生标签、菜单路由和 Quick Look 的窗口检查通过 LaunchServices（open -n -W）运行，避免直接执行二进制时应用未获得主窗口而产生的假失败。日志先清空，再读取 JSON 的 passed 字段，不能把 open 的退出码当作测试通过。自身视图导出不读取外部屏幕，玻璃标题栏不纳入图片验收。

## v0.3 补充决策

### D036：身份化的逆操作复用文件任务

FileUndoHistory 保存成功结果的逆操作，逆操作仍经应用级串行队列、协调器、不覆盖提交和日志。撤销不依赖旧路径直接删除；移动/改名验证当前对象和原父目录，新建验证身份、修改戳与空内容，只移入废纸篓。部分失败保留剩余步骤，不重复执行已经撤销的项目。内部逆操作沿用外层任务 id，避免大小写改名的 staging 留下伪造的中断日志。最多保留 50 个条目，恢复日志只重建历史，不自动执行。

编辑菜单固定交给 AppDelegate，文本编辑器优先处理撤销；其他情况下交给当前浏览页的共享历史。Ctrl+Z 仅在 Windows 列表模式接收。复制、废纸篓逆操作和文件重做继续延后。

### D037：原生 URL 拖放与稳定落点

NSTableView/NSOutlineView 提供标准 file URL pasteboard writer，FileDragState 固定实际开始拖动的引用。FileDropController 缓存拖动序号/pasteboard changeCount，修饰键变化只重新计算策略，悬停不做同步磁盘读取。外部 URL 身份在放手后异步捕获；准备阶段可取消且计入退出忙碌检查。列表行和侧栏落点固定目录身份，防止排序/刷新改变目标。标签使用公开 NSWindowTab.accessoryView 文件夹图标；悬停切换，放手走同一队列。外部导出仅复制，不在拖动结束回调删除来源。

### D038：按真实窗口组保存完整会话

WorkspaceController 从 NSWindowTabGroup 读取实际顺序与选中页。WorkspaceSnapshot v1 包含全部窗口分组、页面目录、身份化选择/锚点和每页视图状态；每秒捕获元数据，沿用 PreferencesController 防抖和原子保存，退出等待落盘。恢复逐页追加到前一页之后，避免三页以上顺序反转。先完成页面读取再恢复选择与过滤，最后选中原活动窗口。

不可用目录保持原标签与保存状态，可之后刷新恢复；同名替换项目不选中。兼容旧单目录配置，配置损坏仍备份。过滤从 v0.3 起随页面会话保存，覆盖 D029 的“不持久化”安排；完整会话恢复覆盖 D032 的延后安排。资源边界为 16 MB、64 组/512 页和每页 10,000 个选中引用。

### D039：跨进程恢复验收

scripts/check-workspace.py 启动生产/恢复两个独立应用进程，使用 PATHDECK_TEST_PREFERENCES 指向 /private/tmp/PathDeck-Session-* 的专用设置。第一个进程退出后，检查器才改名目录和文件、替换一个选中对象，再启动第二个进程核对恢复结果。清理只允许具有精确标记且位于系统临时目录下的 PathDeck-smoke-* 夹具。不会改动用户工作区、实际偏好或剪贴板。
